DODO 창호 견적 관리 V45

핵심 변경
1. 담당자가 견적 작성 시 입력한 창호 순서를 공식 순서로 고정합니다.
   - 수정 화면 / 상세 내역 / 내부용 / 고객용 모두 동일한 순서를 사용합니다.
   - sort_order가 없는 기존 견적은 기존 DB id 순서를 최초 저장 순서로 간주합니다.
2. 요율을 창별 데이터에 함께 저장합니다.
   - DB에 pricing_rate 컬럼이 있으면 창호 항목 자체에 저장합니다.
   - 구버전 DB에서도 estimates.extras_data.windowRates로 호환됩니다.
3. 기존 견적 수정 시 요율 변경을 포함한 금액을 다시 계산합니다.
   - 수정 저장하면 기존 customerFinalAmount를 제거하고 새 계산값으로 갱신합니다.
4. 실행가 엑셀 공식 구현
   (완성창 DC + 유리 DC) × 요율
   + (시공비 + 장비/철거/타일 + 실측/몰딩/보양) × 1.1
   - 실행가 원본 계산 결과를 1만원 단위 올림하여 창별 표시금액으로 사용합니다.
5. 실행가 엑셀에서 확인 가능한 24/27/31/43평의 실제 캐시 데이터를 assets/execution-pricing-v45.json으로 포함했습니다.
   - 평형대 선택은 20→24평, 30→31평, 40→43평, 50평 이상→43평 실행가 기준을 우선 사용합니다.
   - 동일 제품/치수가 여러 실행가 시트에 있으면 선택된 기준 평형을 우선합니다.
6. 실행가 원본 데이터에 정확히 없는 제품/치수는 기존 제품 가격표로 계산합니다.
   - 이 경우 내부 상세에서 '가격표'로 표시됩니다.

Supabase
- supabase-migration-v45.sql을 Supabase SQL Editor에서 1회 실행하면 sort_order/pricing_rate가 DB에 저장됩니다.
- 마이그레이션을 아직 실행하지 않아도 앱은 기존 스키마에 호환되도록 동작합니다. 다만 창별 pricing_rate 영구 저장은 extras_data 호환 방식으로 유지됩니다.

테스트 권장
- 기존 견적을 열고 수정합니다.
- 창호 순서가 최초 입력 순서와 같은지 확인합니다.
- 거실발코니 F-140 2600×2300에 1.75를 넣습니다.
- 24평대 기준이면 실행가 공식으로 원가 계산값 약 2,625,457원이 나오고 창별 표시금액은 2,630,000원이어야 합니다.
- 안방발코니 1.75 → 1,760,000원
- F-250I 1500×1200 1.35 → 1,480,000원
- 거실분합 F-230WF 2600×2400 1.25 → 1,890,000원
- 안방내창 F-230W 2400×1800 1.18 → 1,310,000원
- 요율을 수정하고 저장한 뒤 상세/내부/고객용 총액도 함께 바뀌는지 확인합니다.
