V69 행사 현황 재행사 검토

적용
1. Supabase SQL Editor에서 supabase-migration-v69-event-review.sql 전체 실행.
2. GitHub 파일 업로드/덮어쓰기 후 Vercel 배포 및 새로고침.
   V68 비용 SQL을 아직 실행하지 않았다면 v68-event-costs.sql도 먼저 실행해주세요.
   행사 현황 최초 적용은 v64-events.sql → v68-event-costs.sql → v69-event-review.sql 순서입니다.

행사 현황에서 단지명을 눌러 수정하거나 새 행사를 추가합니다.
- 지역: 직접 입력, 기존 지역 자동완성.
- 검토 단계: 미검토 / 우선 재협약 / 조건부 재협약 / 보류 / 재진행 제외.
- 판단 이유: 복수 선택 태그.
- 메모: 재협약 조건 등 자유 입력.
- 재검토 예정월: 선택 입력.
- 지역/검토 단계 필터로 후보를 추려볼 수 있습니다.

같은 단지명과 지역의 과거 행사 기록을 수정 화면에서 함께 확인합니다.
검토 내용은 행사별로 저장되며, 같은 단지의 다른 행사 기록을 자동으로 덮어쓰지 않습니다.
단지명이나 지역을 다르게 입력하면 별도 단지로 구분됩니다.
비용 미등록/실적 미입력일 때 참고 수치는 계산 불가로 표시합니다.
계약금액에서 행사비만 뺀 금액을 순수익으로 표시하지 않습니다. 자동 등급 산정 없음.

지역·단계 필터와 입력 검증, 모의 저장 후 다시 열기, 기존 견적/비용/신청서 연결 검사 통과.
실제 Supabase 저장 및 모바일 화면은 적용 후 확인해주세요.
단지개발·관리소 영업 일지는 다음 작업입니다.
