V72 단지 개발 / 관리소 영업 일지

적용 순서
1. Supabase SQL Editor에서 supabase-migration-v72-development.sql 전체 실행.
2. supabase-seed-v72-development.sql 전체 실행. 기존 249개 단지 / 512개 기록이 들어갑니다.
3. 압축을 풀어 기존 GitHub 파일을 업로드/덮어쓰기합니다. Vercel 배포 후 새로고침.
두 SQL은 재실행 가능하며, 초기 자료 SQL은 이미 등록한 기록이나 사용자가 수정한 현재 상황을 덮어쓰지 않습니다.
이전 V64/V68/V69 SQL을 이미 실행했다면 다시 실행할 필요 없습니다.

메인 순서: 행사 현황 → 단지 개발 → 실행가 엑셀 파일 생성 → 신청서 엑셀 파일 생성.

사용 방법
- 단지 추가 / 기존 단지 선택 → 단지 정보 수정 가능.
- 단지명·다른 이름·주소·일지 내용 검색 (띄어쓰기/아파트 표기 차이 완화).
- 시·구·동 지역, 확인 예정월, 미처리/확인 완료, 진행 상황 필터.
- 준공연도 시작/종료를 같은 연도로 선택하면 1년 단위 검색.
- 세대수: 200 미만 / 200~499 / 500~999 / 1000~1999 / 2000 이상. 복수 선택 가능.
- 연도나 세대수 미입력 단지만 따로 검색 가능.
- 이번 달 미처리 / 지난달 미처리 바로 보기.
- 단지 선택 → 영업 일지·확인 결과 등록.
- 방문·통화·메일 날짜와 작성자를 기록하며 담당자 검색 필터는 두지 않습니다.
- 이번 달 말 / 다음 달 말 확인은 일지 날짜 기준으로 저장. 정확한 확인 날짜 선택 가능.
- 결과를 등록하면 현재 진행 상황과 다음 확인 일정이 함께 저장됩니다. 과거 일지는 유지.
- 확인 완료를 선택하면 해당 월의 확인 이력은 남고 미처리 목록에서는 제외됩니다.
- 다음 달로 넘기려면 다음 달 말 확인 + 미처리로 저장합니다.

기존 자료 처리
단지개발 내용 모음과 ※ 단지관리의 텍스트 및 엑셀 내용을 포함했습니다.
같은 주소의 반복 기록은 단지별로 묶고 이름 차이는 다른 이름으로 보존합니다.
날짜 불명 기록은 임의 날짜를 넣지 않으며, 원문 출처와 자료 월을 표시합니다.
메모의 진행 상황과 확인월은 초기 분류이므로 모든 초기 단지에 ‘초기 자료 확인 필요’를 표시합니다.
날짜 없는 최신 요약은 과거 확정 방문보다 자동 우선하지 않습니다. 단지 상세에서 원문들을 확인해 현재 상황을 등록해주세요.
영업 일지를 새로 저장하면 이 확인 표시는 해제됩니다.
내용은 유지하되 정확한 단지명/주소/연락처/비용 조건은 단지 정보 수정에서 보완할 수 있습니다.
기존 자료 원문 버튼으로 전체 원문도 열 수 있습니다.
관리소가 같은 다른 단지는 임의로 합치지 않습니다. 이름/주소가 부족한 묶음 기록은 확인이 필요합니다.
협의된 행사비나 게시판 단가는 실제 행사 지출로 자동 등록하지 않습니다.

검증
PostgreSQL 격리 테스트에서 스키마·권한·초기 이관·중복 방지·일지와 현재 상황 동시 저장·재시도·오류 시 롤백 확인.
DOM 테스트에서 목록/상세/원문/연도·세대수 검색/월 변경/저장·수정 확인. 기존 행사·견적·신청서 연결 검사 통과.
실제 Supabase 서버 적용과 PC/모바일 화면은 배포 후 확인해주세요.
